## §1. 연구 질문과 범위

### §1.1 한 줄 진술

엣지 NPU로 내려보낼 로봇 조작 정책의 INT8 변형들을, **실기 실행 없이 오프라인에서만** 심사하여
배포 불가 변형을 사전에 걸러낼 수 있는가.

### §1.2 왜 이게 질문이 되는가

양자화된 정책은 오픈루프 지표(per-state action MSE)가 멀쩡해도 클로즈드루프에서 실패할 수 있다.
오차의 **크기**가 아니라 **방향**이 태스크 성공에 민감한 축과 정렬될 때 실패가 발생한다는 것이
작업가설이다. 이 가설은 이전 작업에서 부분적으로 자기반증된 적이 있으므로(§7.3),
본 계획서는 **정렬 기반 점수가 크기 기반 점수를 이긴다는 결과와 이기지 못한다는 결과를
동등하게 보고 가능한 형태**로 설계한다.

### §1.3 범위 밖 (명시적 제외)

- 양자화 기법 자체의 개선 — 본 연구는 진단이지 최적화가 아니다
- 다중 백엔드 일반화 (Hailo-8 / Coral / QNN) — §9.2 참조, 기본값은 Jetson 단일
- VLA급 모델의 양자화 — GR00T는 FP 레퍼런스로만 사용, 양자화 대상 아님
- 에이전트 레이어(§6)의 성능 주장 — 해커톤 산출물이며 과학적 claim이 아님

## §4. 변형 그리드 (`VC` 시리즈)

### §4.1 요인 설계

INT8 셀 = 캘리브레이션 크기 4 × 캘리브레이션 구성 3 × 양자화 granularity 2 = **24 셀**

| 축 | 수준 |
|---|---|
| `calib_size` | 16 / 64 / 256 / 1024 |
| `calib_composition` | success-only / mixed(복구 궤적 포함) / late-phase-only |
| `granularity` | per-tensor / per-channel |

여기에 비-INT8 기준 arm 추가:

| 코드 | 내용 | 역할 |
|---|---|---|
| `VC-000` | FP32, GX10 | 상한 기준선 |
| `VC-025` | FP16, Jetson TRT | 정밀도 축 대조 |

**총 26 셀** (`VC-000`, `VC-001`–`VC-024`, `VC-025`).
셀 번호와 요인 조합의 매핑 테이블은 `configs/variant_grid.yaml`에 고정하고 해시를 기록한다.

### §4.2 통제 원칙

- 한 번에 한 변수. 셀 간 차이는 위 세 축 외에는 없어야 한다
- 모든 셀은 **동일한 FP32 체크포인트 하나**에서 파생된다. 재학습 금지
- 캘리브레이션 데이터는 전부 `train` 분할에서만 추출
- TRT 빌드 옵션(workspace, tactic source 등)은 셀 간 동일하게 고정

### §4.3 캘리브레이션 구성 축을 넣는 이유

과거 툴체인 조사에서 캘리브레이션 세트 크기가 **문서화되지 않은 기본값**으로 동작하고,
최적화 레벨이 누적이 아니라 치환으로 동작하는 등, 문서와 실제 동작이 반복적으로 어긋났다.
따라서 본 계획에서는 TRT의 실제 캘리브레이션 동작을 **소스/API 레벨에서 직접 확인**한 뒤
그리드를 확정한다. 문서만 믿고 축을 설계하지 않는다.

## §5. 감사 점수 (오프라인 스크리닝)

### §5.1 두 개의 경쟁 점수

두 점수를 **동시에, 같은 데이터로** 산출한다. 어느 쪽이 이기는지가 `H2`다.

**`score_mag` (크기 기반, 비교군)**
`audit` 버퍼 2,000 상태에서 INT8 정책과 FP32 정책의 행동 차이 L2 노름의 상위 분위수 통계.

**`score_align` (정렬 기반, 주장군)**
동일한 행동 오차 벡터를 **태스크 민감 방향**에 투영한 성분의 크기 통계.

민감 방향 산출:
1. `train` 분할로 태스크 진행도 회귀기(task-progress regressor) `g(s)`를 학습
2. 상태별 민감 방향 = 행동에 대한 `g`의 국소 민감도 (유한차분 또는 자동미분)
3. 정렬 성분 = 행동 오차를 이 방향에 투영한 값

`g`는 `train`만으로 학습하며, `audit` 버퍼는 투영 계산에만 쓴다 (`IG-2`).

### §5.1b 공짜 예측기 비교군 (`score_cheap` 시리즈)

감사 파이프라인의 진짜 경쟁 상대는 정교한 대안이 아니라 **실무 기본값**이다.
아래 셋은 계산 비용이 0에 가까우므로 전부 산출하고, 각각 순위를 만든다.

| 코드 | 예측기 | 근거 |
|---|---|---|
| `score_cheap_A` | "`calib_size` 최대 + per-channel" 고정 휴리스틱 | 실무에서 가장 흔한 기본 선택 |
| `score_cheap_B` | 홀드아웃이 아닌 `train` 상태에서의 오픈루프 action MSE | 대부분의 팀이 실제로 보는 지표 |
| `score_cheap_C` | Jetson 추론 지연 (태스크와 무관한 축) | 무의미 예측기. 파이프라인 sanity check |

`score_align`이 `score_cheap_A`/`_B`를 이기지 못하면, 감사 파이프라인은 **불필요하다는 것이 결론**이며
그렇게 보고한다. `score_cheap_C`가 이기면 실험 설계에 결함이 있다는 신호다.

### §5.2 점수 → 순위

두 점수 각각에 대해 25개 INT8/FP16 셀의 전체 순위를 만든다.
이 순위는 **실기 시행 전에 동결**된다 (§8 `LOCK-2`).

### §5.3 Jobs 팬아웃 스펙

- 작업 단위: (variant cell) × (bootstrap replicate)
- 셀당 상태 2,000, bootstrap 200 리샘플 → 셀별 점수 CI 산출
- 총 잡 수 ≈ 26 × 200 = 5,200 (배치 묶음으로 제출)
- 각 잡의 산출물: 점수 스칼라 + 상태별 오차/정렬 성분 벡터 + 환경 메타데이터(TRT 버전, 드라이버, 빌드 해시)
- 아티팩트는 불변 스토리지에 기록하고 매니페스트 해시를 커밋

## §7. 가설과 엔드포인트

### §7.0 설계 원칙 — 극단 대조를 주 엔드포인트로 쓰지 않는다

상위 그룹 vs 하위 그룹 대조는 감사기의 예측력이 평범해도 큰 격차를 만든다.
셀 간 성공률 분산이 크기만 하면 격차의 상당 부분은 **측정이 아니라 구성**에서 나온다.
과거 유사 설계에서 극단 대조군 효과가 measured-minus-random 대조를 압도해,
효과 크기의 지배적 출처가 구성이었던 사례가 있다.

따라서 주 엔드포인트는 **"감사기가 무작위 선택보다 나은가"**로 정의한다.
극단 대조는 분산 존재 확인용 부 엔드포인트로 격하한다.

### §7.1 실기 arm 구성

감사 점수 동결(`LOCK-2`) 직후, 아래 arm을 확정하고 봉인한다.

| arm | 선정 방식 | 셀 수 | trial/셀 | 소계 |
|---|---|---|---|---|
| `ARM-AUDIT` | `score_align` 상위 3셀 | 3 | 25 | 75 |
| `ARM-RANDOM` | 나머지 셀에서 커밋된 시드로 무작위 3셀 | 3 | 25 | 75 |
| `ARM-LOW` | `score_align` 하위 2셀 | 2 | 15 | 30 |
| `ARM-FP32` | `VC-000` | 1 | 25 | 25 |
| `ARM-RETEST` | `ARM-AUDIT` 중 1셀을 별도 세션에서 재측정 | 1 | 20 | 20 |
| | | | **합계** | **225** |

- `ARM-RANDOM` 추출 풀은 `ARM-AUDIT`·`ARM-LOW`에 선정된 셀을 제외한 나머지 전체
- `ARM-FP32`는 **같은 무작위 인터리브 블록 안에서** 실행한다. 별도 세션 기준선은
  조명·지그·마모·조작자 드리프트와 교란되므로 쓰지 않는다 (`IG-8`)
- `ARM-RETEST`만 의도적으로 다른 세션에 배치한다 (§7.3의 노이즈 바닥 추정용)

### §7.2 주 가설

**`H1`** — 감사 점수로 고른 셀은 무작위로 고른 셀보다 실기 성공률이 높다.

- **`EP-1` (주 엔드포인트)**: `ARM-AUDIT` 풀링 성공률 − `ARM-RANDOM` 풀링 성공률
- 표본: 75 vs 75
- 추정량: 두 비율의 차이, 95% CI (Newcombe), 검정은 two-proportion
- **검정력 사전 고지**: 셀 성공률이 대략 균등 분포라면 `ARM-RANDOM` 기대값은
  상·하위의 중간에 놓인다. 0.80 vs 0.62 가정 시 n=75/75에서 검정력은 약 0.65에 그친다.
  이는 설계 결함이 아니라 **결정 관련 대조가 본질적으로 더 어렵기 때문**이며,
  해커톤 일정 내에서 해소 불가능하다
- **사전 약정**: 이진 유의성 결론 대신 **효과 크기와 CI 폭**을 결론의 단위로 보고한다.
  CI가 0을 포함하면 "격차를 검출하지 못했다"로 쓰고, "효과가 없다"로 쓰지 않는다

### §7.3 부 가설

**`H2`** — 정렬 기반 점수가 크기 기반 및 공짜 예측기보다 스크리닝을 잘한다.

- **`ES-1`**: `score_align` 순위 상위 3셀 vs `score_mag` 순위 상위 3셀의 성공률
- **`ES-2`**: `score_align` 상위 3셀 vs `score_cheap_A`(최대 calib + per-channel) 성공률
- **`ES-3`**: `score_align` 상위 3셀 vs `score_cheap_B`(오픈루프 MSE) 상위 3셀 성공률
- 점수들의 상위 3셀은 겹칠 수 있다. 겹치는 셀은 **trial을 공유**한다 (재실행 금지)
- 겹침이 심해 대조가 성립하지 않으면 그 사실 자체가 결과다.
  **"정교한 점수와 공짜 휴리스틱이 같은 셀을 고른다"는 것은 유효한 음성 결과이며,
  이 경우 감사 파이프라인이 불필요하다는 결론을 그대로 쓴다**

**`H3`** — 극단 간 분산이 존재한다 (감사기 유효성이 아니라 문제 존재 여부 확인).

- **`ES-4`**: `ARM-AUDIT` − `ARM-LOW` 성공률 차이
- 이 값이 크다고 해서 `H1`이 지지되는 것이 아니다. **`EP-1`과 `ES-4`를 반드시 나란히 보고**하고,
  둘의 크기 차이를 명시적으로 논한다. `ES-4` >> `EP-1`이면 효과의 지배적 출처가 구성임을 뜻하며
  이를 눈에 띄게 공개한다

### §7.4 노이즈 바닥

- **`ES-5`**: `ARM-RETEST`와 원 세션 동일 셀의 성공률 차이
- 이 값이 `EP-1`과 비슷한 크기면 **`EP-1`은 해석 불가**다. 결론에서 이 비교를 생략하지 않는다
- `ARM-FP32` 25 trial도 세션 내 기준선으로 함께 보고한다

### §7.5 다중 비교

`H1`(`EP-1`)과 `H2`(`ES-1`–`ES-3`)에 대해 Holm 보정.
`ES-4`, `ES-5`는 해석 보조 지표이므로 보정군에서 제외하고 그렇게 명시한다.

### §7.4 기술 통계 엔드포인트 (검정 없음)

- **`EX-1`**: 셀별 실패 유형 분포 (miss / collision / drop / timeout / unsafe)
- **`EX-2`**: 셀별 Jetson 추론 지연 분포
- **`EX-3`**: `D4` 런타임 감독자의 개입 횟수, 오탐 abort 횟수, 개입 지연
- **`EX-4`**: 오프라인 점수의 분포 구조 — 군집/이상치 여부

> `EX-4`를 명시적으로 넣는 이유: 과거 유사 분석에서 점수가 **양봉(bimodal) 구조**를 보여
> 양성 셀 군집과 병리적 이상치가 분리된 적이 있다. 이런 구조가 나오면 순위 상관은
> 이상치 몇 개가 끌고 가는 허상이 된다. 리뷰어가 먼저 발견하면 체리피킹으로 읽히므로
> **선제 공개**한다.

## §8. 무결성 가드와 순서 잠금

| 코드 | 내용 |
|---|---|
| `IG-1` | `audit` 분할은 학습·캘리브레이션 경로에서 로더 assert로 차단 |
| `IG-2` | 진행도 회귀기 `g`는 `train`만으로 학습 |
| `IG-3` | 모든 셀은 단일 FP32 체크포인트에서 파생, 재학습 없음 |
| `IG-4` | 실기 trial 순서는 커밋된 시드에서 랜덤 인터리브. 셀별 블록 실행 금지 |
| `IG-5` | **운영자 블라인딩**: 러너 스크립트가 다음 trial의 셀을 선택하되 화면에 표시하지 않고 봉인 로그에만 기록. 조작자는 어느 변형이 도는지 모른 채 리셋·판정한다 |
| `IG-6` | 성공 판정 규칙은 실기 시작 전에 문서로 고정. 실행 중 수정 금지 |
| `IG-7` | `ARM-RANDOM`의 3셀은 `LOCK-2` 직후 커밋된 시드로 추출하고 해시를 기록. 추출 후 교체·재추출 금지 |
| `IG-8` | `ARM-FP32`는 테스트 arm과 동일 블록에 인터리브. 별도 세션 기준선 사용 금지 |
| `IG-9` | 모든 점수(`score_align`, `score_mag`, `score_cheap_A/B/C`)의 순위를 **동시에** 동결한다. 실기 결과를 본 뒤 점수 정의를 조정하는 경로를 차단 |

**순서 잠금 (`LOCK`)**

- `LOCK-1` — 데이터 분할 확정 → 이후 정책 학습 시작
- `LOCK-2` — **감사 점수 전량 산출·동결·해시 커밋 → 이후 최초 실기 trial 실행.**
  이 순서가 깨지면 연구 전체의 신뢰성 자산이 사라진다. 가장 중요한 잠금
- `LOCK-3` — 실기 120 trial 완료 → 이후 통계 분석 스크립트 최초 실행
- `LOCK-4` — 분석 완료 → 이후 영상 편집·서사 구성

## §9. 미결 항목 (freeze 전 확정 필요)

### §9.1 정책 아키텍처 — 기본값 **ACT**

SmolVLA는 VLA 서사가 좋지만 export/양자화 경로가 훨씬 험하다. `G3` 리스크가 배가된다.
**결정 필요 시한: 즉시** (드라이런 내용이 이걸로 갈림)

### §9.2 백엔드 범위 — 기본값 **Jetson 단일**

Hailo-8 추가 시 ACT의 어텐션이 컴파일러에서 막힐 가능성이 있고, 과거 해당 툴체인은
문서와 실제 동작이 반복적으로 어긋났다. 제출은 Jetson으로, Hailo는 future work 한 줄.
**결정 필요 시한: `G2` 종료 시점**

### §9.3 감사 지표 출처 — **확인 필요, 내가 판단할 사안 아님**

기존 미발표 연구의 정렬 기반 지표를 그대로 재사용하면 `G4`가 거의 공짜가 된다.
다만 해커톤은 **Apache 2.0 공개 리포지토리를 요구**하고, 심사 대상이다.
진행 중인 학회 제출과의 선행공개·중복 문제가 없는지 확인이 필요하다.
회피 경로: 해커톤용으로는 단순화된 공개 버전(진행도 회귀기 기반 투영)만 구현하고,
원 지표는 참조하지 않는다. **결정 필요 시한: `G1` 종료 시점**

## §13. 보고 원칙

- 모든 비율은 점추정 + 95% CI를 함께 보고한다. 점추정 단독 보고 금지

  결과 열람 여부를 기록한다. 원 계획을 조용히 덮어쓰지 않는다
- 과장된 표현을 쓰지 않는다. "검증했다"가 아니라 "이 조건에서 이렇게 관측되었다"
