# 사전등록 v0.2 반영, 5개 점수와 arm 구성, `ES-1`–`ES-3` 커버리지 결함 발견

## Scope

사전등록이 v0.1 → v0.2로 갱신됨에 따른 구현 재정렬. §5.1b(공짜 예측기), §7.0–§7.5(arm 재구성),
`IG-7`–`IG-9`가 대상이다.

**하지 않은 것**: 데이터 수집 없음, 정책 학습 없음, TRT 빌드 없음, 실기 trial 없음,
Nebius 호출 없음. 이 시도의 모든 수치는 합성 데이터 또는 구조적 계산이다.

## v0.2의 주요 변경과 구현 영향

- 주 엔드포인트가 극단 대조(top3−bottom3)에서 **measured-vs-random**
  (`ARM-AUDIT` vs `ARM-RANDOM`)으로 이동. 극단 대조는 `ES-4`로 격하
- 비교군에 공짜 예측기 3종 추가 → 점수가 2개가 아니라 **5개**
- 실기 표본 120 → **225**
- 비율 차 CI가 Wilson → **Newcombe**
- `IG-9`: 5개 점수 순위를 **동시에** 동결

## 변경

- `docs/preregistration.md`를 v0.2로 교체, `docs/decision_log.md`에 개정으로 기록
- **사전등록이 위임한 자유도를 결과 열람 전에 고정**했다. §5.1은 "상위 분위수 통계"라고만
  하고 통계량을 지정하지 않았으므로, 지금 **상위 10% 조건부 평균(CVaR@90)**으로 못박았다.
  단일 분위수는 부트스트랩에서 소수 상태에 의해 튄다. q50/q90/q95/q99/max는 `EX-4`
  진단용으로 저장하되 순위 산출에는 쓰지 않는다
- `src/edgeqgate/progress.py` — 진행도 회귀기 `g`.
  §5.1은 `g(s)`로 쓰고 민감 방향을 "행동에 대한 `g`의 국소 민감도"로 정의하는데, `g`가
  상태만 받으면 `∂g/∂a`가 동역학 모델 없이는 정의되지 않는다. 따라서 **`g(s, a)`**
  (상태 s에서 행동 a 실행 후 도달하는 진행도)로 구현했다.
  랜덤 푸리에 특징 + 릿지를 쓴 이유는 성능이 아니라 **해석적 기울기**다. 유한차분은
  스텝 크기라는 자유도를 지표에 넣고 그 값이 셀 순위를 바꿀 수 있다
- `src/edgeqgate/scores.py` — 5개 점수. 전부 "낮을수록 안전" 방향으로 정규화.
  `ranking_hash()`가 5개 중 하나라도 빠지면 예외(`IG-9`)
- `src/edgeqgate/arms.py` — §7.1 arm 구성, `IG-7`(무작위 3셀 커밋 시드 추출),
  §12의 사전 고정 축소 순서, 그리고 아래 커버리지 점검

## 관측

### 구조적 (합성 데이터 아님, 그리드 정의만으로 결정)

- `score_cheap_A`의 상위 3셀은 **데이터를 보기 전에 이미 확정**된다:
  `VC-020`, `VC-022`, `VC-024` (calib_size=1024 × per-channel × 구성 3종).
  §7.3의 `ES-2`가 정확히 3셀 대조로 성립한다는 뜻이라 이 점은 설계에 유리하다

### `ES-1`–`ES-3` 커버리지 결함 (이 시도의 주요 발견)

§7.1의 arm 표는 `score_align`의 상위 3·하위 2셀과 무작위 3셀에만 trial을 배정한다.
그런데 §7.3의 `ES-1`은 `score_mag` 상위 3셀의, `ES-3`은 `score_cheap_B` 상위 3셀의
성공률을 요구한다. **이 셀들이 어느 arm에도 없으면 실기 데이터가 아예 없어 계산 불가**다.
§7.3은 "겹치는 셀은 trial을 공유한다"고만 하고 겹치지 않는 경우를 다루지 않는다.

순위 무상관을 가정한 몬테카를로 4,000회 (합성):

| 엔드포인트 | 완전 계산 가능 비율 |
|---|---|
| `ES-1` (`score_mag` top3) | 2.2% |
| `ES-2` (`score_cheap_A` top3) | 2.3% |
| `ES-3` (`score_cheap_B` top3) | 2.2% |
| 셋 다 계산 불가 | 93.3% |

해석상 주의:

- `score_mag`와 `score_align`은 **같은 오차 벡터에서 나오므로** 실제 순위는 상관이 높을
  것이고, `ES-1`의 실제 커버리지는 위 2.2%보다 상당히 나을 것으로 예상한다.
  위 숫자는 상관 0일 때의 하한이다
- 반면 `score_cheap_A`는 데이터와 무관하게 고정이므로 **`ES-2`에는 위 숫자가 그대로 적용된다**.
  `VC-020`/`VC-022`/`VC-024`가 `score_align` 상위 3·하위 2에 들거나 `ARM-RANDOM`에
  뽑히지 않는 한 `ES-2`는 계산되지 않는다
- `score_cheap_C`(지연)는 §7.3의 `ES` 대조에 직접 등장하지 않아 이 점검에서 제외했다.
  §5.1b는 "`score_cheap_C`가 이기면 설계 결함"이라고만 하고 대조 엔드포인트를 주지 않는다

`arms.coverage_report()`가 이 점검을 `LOCK-2` 시점에 수행한다. 실기 종료 후에 발견하면
손쓸 방법이 없고, 사후에 trial을 추가하면 blinding(`IG-5`)과 인터리브(`IG-4`)가 깨진다.

### 합성 데이터 위의 동작 확인

- `g`의 해석적 기울기 vs 유한차분 최대 오차 `2.98e-11` — 구현 검증이며,
  파이프라인은 유한차분을 쓰지 않는다
- `g`가 행동 축 0에만 민감하도록 만든 장난감 문제에서 민감 방향의 축 0 성분이
  다른 축의 약 2배 (0.629 vs 0.318–0.365)
- 정렬 성분 ≤ 오차 노름 (코시-슈바르츠) 전 상태에서 성립
- arm 총 trial 225 = §7.1 사양과 일치. `ARM-AUDIT`∩`ARM-RANDOM` = 공집합
- 같은 시드·같은 순위에서 `plan_hash` 재현됨

## Verification

- 여전히 `pytest` 스위트가 없다. 위 확인은 전부 일회성 스크립트다 — 다음 시도의 우선 항목
- `ARM-RETEST`의 대상 셀 선택 규칙이 §7.1에 없다. 사람이 고르면 결과를 본 뒤 고르는 경로가
  열리므로 **커밋된 시드로 결정**하도록 구현하고 이 노트에 기록한다.
  사전등록 본문에 명시되어야 할 항목이며 현재는 구현이 앞서 있다
- `G0` 통과 기준(TRT INT8 빌드 1회 성공) **여전히 미충족**
- Nebius 자격증명 부재로 §14 액션 4 미착수

## 주장하지 않는 것

- 위 몬테카를로는 `score_align`의 순위 분포에 대한 **가정** 위의 계산이다.
  실제 커버리지는 실제 점수가 나와야 알 수 있다
- `g`가 장난감 문제에서 올바른 축을 집었다는 것은 구현이 동작한다는 뜻이지,
  실제 조작 정책에서 태스크 민감 방향을 잘 잡는다는 근거가 아니다
- 5개 점수가 산출 가능하다는 것과 그중 무엇이 스크리닝을 잘하는가는 별개다.
  후자는 `LOCK-2` 이후 실기로만 알 수 있다
