## 철회

attempt-025와 이 attempt 초반의 **TRT 출력 비교는 전부 균일 난수 이미지를 입력**으로 썼다.
캘리브레이션한 활성화 범위 밖이라 INT8이 심하게 포화했고, 그 포화 거동이 추첨·빌드마다 갈렸다.
같은 엔진에 **실제 train 프레임**을 넣고 다시 쟀다.

| 비교 | 난수 입력 | 실제 프레임 |
|---|---|---|
| 빌드 추첨 (`VC-001` ×2, 캐시 없음) | 0.688% | **0.558%** |
| 추첨 대조군 (`VC-001` vs `VC-003`) | 7.527% | **0.549%** |
| granularity (`VC-001` vs `VC-002`) | 1.192% | **0.742%** |
| calib_size (`VC-001` vs `VC-013`) | 0.960% | **0.583%** |
| 추첨 노이즈 `calib_size=16` | **146.5%** | **0.536%** |
| 추첨 노이즈 `calib_size=64` | 0.827% | 0.507% |
| 추첨 노이즈 `calib_size=256` | 1.310% | 0.513% |

"크기 16에서 파국적 추첨"은 **철회한다.** 분포 밖 입력의 인공물이었다.
PyTorch fake-quant로 추첨 20회 × 크기 3종을 train 프레임 32개로 평가한 결과도 같다:
파국 0/20, FP32 상관 최소 0.999, 추첨 간 거리 중앙 0.46–0.51% (`artifacts/g0/draw_distribution.json`).

**연속된 두 측정 경로(TRT 실측과 fake-quant)가 어긋났을 때 하나가 틀렸다고 보고 확인한 것**이
이 철회를 만들었다.

## 철회되지 않는 것

- TRT 빌드가 재현되지 않는다 (md5 6개 전부 다름)
- 동결 캐시가 그 추첨을 제거한다 (e–f 출력 비트 일치 — 입력과 무관한 동일성)
- 빌드 간 **지연** 산포 0.95 ms — trtexec 지연 측정은 출력값 비교와 별개다
- attempt-022의 `build_grid.py` composition 축 미구현 버그

## `manual_actions.md` #13·#14의 근거 수치 정정

두 항목은 "출력 상대 L2 1.2%"를 인용한다. 실제 프레임 기준으로는 **~0.56%**다.
결론(동결 캐시 권장)은 유지된다. 오히려 강해진다: 실제 입력에서 **빌드 추첨(0.558%)과
축 효과(0.583–0.742%)가 같은 자릿수**이므로, 추첨을 제거하지 않으면 셀 간 비교가
빌드 운과 구별되지 않는다.

## 새로 드러난 것 — 시드에 `cell`이 들어간다

`build_calibration_set`의 시드는 `seed_from(seed, "calibration", cell, composition, calib_size)`다.
**26셀이 전부 독립 추첨**을 받는다. `VC-001` vs `VC-002`(granularity만 다름)도 다른 프레임을 쓴다.
실제 프레임 기준으로 추첨 노이즈(~0.5%)가 축 효과(0.58–0.74%)와 같은 자릿수라서
**요인 효과와 추첨 운이 분리되지 않는다.**

기존 테스트 `test_same_factors_same_frames_regardless_of_cell_code`가 이 모호함을 이미 적어두었다
("셀 간 차이가 요인 조합에서만 오도록 하려면 오히려 같아야 한다는 주장도 가능하다").

제안: 시드에서 `cell`을 빼고, `calib_size`는 **중첩 표본**(같은 셔플 순서의 앞 N개)으로.
그러면 granularity 대비는 동일 프레임, size 대비는 "프레임 추가"가 된다.
§4.1은 추첨 시드 구성을 명시하지 않으므로 개정이 아니라 구현 선택이지만, 기존 테스트가
현재 동작을 고정해두었으므로 `decision_log.md`에 남긴다. **미적용** — 사용자 확인 대기.
