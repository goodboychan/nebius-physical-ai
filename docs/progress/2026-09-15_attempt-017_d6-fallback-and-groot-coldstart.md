# `D6` 클라우드 폴백 — 콜드스타트 9.4분, 웜 유지가 필수

## Scope

§6의 `D6`(감사 신호 초과 시 엣지 → 클라우드 전환) 판정·인계 로직을 구현하고,
§12가 리스크로 지목한 **엔드포인트 콜드스타트**를 GR00T 실물 크기로 측정했다.

**하지 않은 것**: 실기 없음. **전체 Isaac-GR00T 스택을 세우지 않았다** —
GR00T는 `auto_map`이 없어 `trust_remote_code`로 로드되지 않고 NVIDIA의 Isaac-GR00T
패키지가 필요하다. 따라서 **실제 추론은 수행하지 않았고** 콜드스타트의 지배적 비용만 쟀다.

## `D6` 콜드스타트 실측 (`gpu-l40s-a`, eu-north1)

`pytorch/pytorch:2.5.1-cuda12.4-cudnn9-runtime` 이미지에서 GR00T-N1.5-3B 가중치를
HF에서 받아 GPU에 적재하기까지.

| 단계 | 시간 | 비중 |
|---|---|---|
| 이미지 풀 + 프로비저닝 | **372.7 s** | **66%** |
| 의존성 설치 | 2.1 s | 0.4% |
| 가중치 5.4 GB 다운로드 | **182.9 s** | 33% |
| GPU 적재 | 3.3 s | 0.6% |
| **합계** | **561 s (9.4분)** | |

적재 확인: 파라미터 **2,724,163,520 (2.72B)**, device `cuda`, GPU `NVIDIA L40S`.

**웜 왕복**: 중앙 **948 ms** (892–973, n=10). 단 이것은 **추론 없는 HTTP GET**이며
GR00T 추론 시간은 여기에 더해진다.

### attempt-008의 119초는 오해를 부르는 수치였다

attempt-008에서 잰 콜드스타트 119초는 `python:3.12-slim` + `http.server`,
즉 **연산도 모델도 없는 컨테이너**였다. 실제 모델을 올리면 **4.7배**다.
그 노트에 "GR00T를 올리면 훨씬 길 것"이라고 한계를 적어두었고, 이제 수치가 나왔다.

## §12의 리스크 판정

> 리스크: Endpoint 콜드스타트가 길어 런타임 폴백 비현실적 → `D6` 서사 붕괴
> 완화: `G0`에서 측정. 길면 **웜 상태 유지** 또는 폴백을 "권고"로 격하

**측정 결과 콜드스타트 상태에서의 런타임 폴백은 불가능하다.** 9.4분은 60초 태스크에
어떤 방식으로도 맞출 수 없다. 따라서 §12의 완화책 중 **"웜 상태 유지"가 강제**된다.

비용 함의: 실기 세션 중에만 띄운다면 §12가 잡은 실기 시간 약 9.5시간 기준
L40S $1.55/h × 9.5h ≈ **$14.7**. 상시 가동(3일)은 $110을 넘는다.
`docs/cost_model.md`의 추정과 부합한다.

**운영 체크리스트 항목이 둘 생겼다** — 둘 다 세션 시작 전에 해야 한다.

1. `D6` 엔드포인트 사전 기동 (콜드스타트 9.4분)
2. `D4` 연결 웜업 (첫 호출 971ms, attempt-016)

## `D6` 폴백 로직 (`src/edgeqgate/fallback.py`)

네트워크에 의존하지 않는 판정·인계만 담는다. 테스트 13건.

### 폴백은 예측적이어야 한다

왕복이 웜 상태에서도 854–948ms인데 ACT 액션 청크는 100스텝 @ 30fps = **3.33초**다.
현재 청크가 소진된 뒤 요청하면 왕복 시간만큼 **제어가 빈다.**
남은 청크가 `rtt + 여유`보다 짧아지는 시점에 미리 보내야 한다.

| | 값 |
|---|---|
| 청크 길이 | 3,333 ms |
| 필요 리드 (rtt 854 + 여유 500) | 1,354 ms |
| 성립 여부 | **성립** |

이 조건이 **청크 길이에 의존한다**는 점이 설계 제약이다. `chunk_steps=20`(667ms)이면
청크가 필요 리드보다 짧아 **예측적 폴백이 성립하지 않는다.** 테스트로 고정했다.
정책 아키텍처를 바꾸면(§9.1) 이 조건을 다시 봐야 한다.

### 폴백을 보수적으로 두는 이유

`docs/success_criterion.md`: *"클라우드 폴백(`D6`) 발동 후 안착 → **실패**로 집계한다.
주 엔드포인트 `EP-1`은 **엣지 정책 단독** 성공률이다."*

따라서 폴백은 성공률을 구하는 장치가 아니라 안전 장치이며, 남발하면 `EP-1`의 표본이
줄어든다. 기본 설정은 **감사 점수만으로는 발동하지 않고** `D4` 감독자의 `FALLBACK`
판정을 함께 요구한다(`require_supervisor_fallback=True`).

### 늦게 도착한 응답

응답이 청크 소진 후 도착하면 `late_arrivals`로 집계하고 **소스를 전환하지 않는다.**
이미 제어가 빈 뒤에 클라우드로 넘기면 상태가 어긋난다. `EX-3`에 남긴다.

## Verification

- **실제 GR00T 추론을 하지 않았다.** 모델 클래스 구성, 워밍업 커널, 추론 지연이 빠져 있다.
  561초는 **하한**이며 실제 GR00T 서빙은 더 걸린다
- 이미지가 `pytorch/pytorch:...-runtime`(약 6GB)이다. Isaac-GR00T 의존성을 넣으면
  이미지가 커지고 풀 시간(현재 66%)이 더 늘어난다
- 웜 왕복 948ms는 **eu-north1 터널** 기준이고 **GB10에서 쟀다.**
  실기 때 요청을 보내는 것은 Jetson이므로 재측정이 필요하다
- 콜드스타트를 **1회만** 측정했다. 이미지 캐시 상태에 따라 달라질 수 있다
- `fallback.py`의 기본 `rtt_ms=854`는 attempt-008(eu-west1, 무연산)의 값이다.
  실제 GR00T 왕복이 정해지면 갱신해야 한다

## 주장하지 않는 것

- GR00T가 실제로 폴백 정책으로 동작한다고 말하지 않는다. 가중치를 GPU에 올린 것까지다
- 948ms 왕복으로 폴백이 실기에서 성립한다고 말하지 않는다. GR00T 추론 시간이 빠져 있다
- 콜드스타트 9.4분이 최적화 불가능하다고 말하지 않는다. 이미지를 줄이거나 가중치를
  이미지에 굽거나 스냅샷을 쓰면 줄어든다. **측정한 것은 소박한 구성의 값이다**
