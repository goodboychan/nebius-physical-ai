# `D5` Errata 수집기와 리트리벌 동결

## Scope

§6의 `D5`(Tavily로 TRT·Orin·컴파일러 known issue 수집)를 구현하고,
그 근거를 재현 가능하게 만드는 리트리벌 동결 모듈을 패키지에 추가했다.

**하지 않은 것**: 실기 없음, 우리 수집 데이터 없음, 검색 결과의 **내용 검증 없음**
(수집만 했고 사실 확인은 사람 몫이다), 일 단위 드리프트 미측정.

## 왜 동결이 필요한가

검색 결과는 시간에 따라 변한다. 사전등록 연구가 검색 결과를 리포트 근거로 쓰면,
나중에 "그때는 이렇게 나왔다"를 검증할 방법이 없다. §12가 재현성을 요구하므로
질의와 응답을 통째로 스냅샷하고 해시를 박는다.

`src/edgeqgate/retrieval.py`:

- `freeze()` — 질의 실행 후 결과·내용 해시를 스냅샷
- `load_snapshot()` — 해시 재계산으로 변조 탐지
- **replay 모드는 동결본이 없으면 예외를 던진다.** 조용히 새 검색을 하지 않는다.
  이것이 동결의 핵심이다 — 재현이라 부르면서 새 데이터를 받으면 의미가 없다
- `drift()` — 두 시점 비교. URL 교체뿐 아니라 **같은 URL의 본문 변경**도 잡는다

내용 해시는 url·title·content만 본다. **점수(score)는 재현성 대상에서 뺐다** —
랭킹 점수가 미세하게 흔들려도 근거 자체는 같기 때문이다. 테스트로 고정했다.

검색 함수를 주입받는 구조라 Tavily에 의존하지 않고, 네트워크 없이 테스트할 수 있다.
테스트 11건.

## `D5` 구현

`scripts/d5_errata_collector.py`. 질의를 **실제 빌드 환경에서 유도**한다 —
손으로 쓴 고정 질의가 아니라 `artifacts/g0/orin_latency.json`의 TRT 버전·디바이스에서
만든다. 환경이 바뀌면 질의도 바뀐다.

수집 결과: 질의 5개, 결과 25건, 고유 URL 22개.
스냅샷 해시 `76f9ba2110c86330…`.

질의가 환경에서 유도되니 결과도 우리 상황을 정확히 친다:

- `TensorRT 10.3.0 Release Notes` (score 0.86) — 배포 대상의 정확한 버전
- `TensorRT Version Mismatch Between DeepStream L4T 7.1 Container and Jetson Orin Nano`
  (score 0.77) — **우리가 실제로 겪은 10.14 vs 10.3 버전 스큐와 같은 부류**

`artifacts/reports/errata.md`로 렌더링되며, 헤더에 스냅샷 해시와
"사람이 검토하기 전까지 사실로 인용하지 말 것"을 박는다.

## Verification

- **검색 결과의 내용을 검증하지 않았다.** URL과 제목이 그럴듯하다는 것뿐이고,
  실제로 우리 상황에 해당하는 known issue인지는 사람이 읽어야 한다
- **일·주 단위 드리프트를 측정하지 않았다.** `--mode drift`를 구현했지만
  한 시점의 스냅샷만 있어 비교 대상이 없다. `LOCK-2`까지의 기간에 재수집해
  흔들림을 재야 `score_folklore`(제안 단계) 같은 검색 기반 점수의 타당성을 판단할 수 있다
- Tavily 결과의 `content` 필드를 1,200자로 잘라 저장한다. 원문 전체를 보관하지 않으므로
  나중에 더 긴 맥락이 필요하면 다시 가져와야 하고, 그때는 내용이 바뀌었을 수 있다
- `D5`를 `D3` 리포트에 **아직 결합하지 않았다.** 두 문서가 따로 생성된다

## 주장하지 않는 것

- 수집된 errata가 우리 빌드에 실제로 영향을 준다고 말하지 않는다. 검색했을 뿐이다
- 동결이 검색 결과의 **정확성**을 보증한다고 말하지 않는다. 보증하는 것은
  "언제 무엇을 받았는지"의 재현성뿐이다
- 이 모듈이 `score_folklore` 제안을 채택 가능하게 만든다고 말하지 않는다.
  그 제안은 여전히 인코딩 함수 설계와 드리프트 측정이 선행되어야 한다
